Methodology: Metrics are calculated at the user level, not raw event level, to avoid overcounting repeated clicks, installs, or feature tries. For each user, the dashboard uses the first LP CTA click, the first install after that click, and the first try_grammarly event after install. Activation requires the ordered sequence LP CTA click → install → try_grammarly within a 7-day attribution window. If a user clicked multiple LP CTAs, first-touch LP attribution is applied. did_click_lp represents an install-button click on the landing page, not a page render — page-render CVR cannot be calculated from this dataset.
Dashboard Summary

I focused the dashboard on behavioral activation quality rather than raw campaign volume. In this dataset, did_click_lp means the user clicked the LP install CTA, did_install_grammarly shows setup completion, and try_grammarly is the first available proxy for product value. Because an install alone does not prove the user reached value, the core KPIs are Install CVR, Activation CVR, Install-to-Try Rate, Dead Install Rate, Repeat Try Rate, and feature adoption by LP.

The dashboard is designed to help the growth team decide what to scale, fix, pause, or investigate. Academic Writing shows stronger activation and repeat behavior, making it a candidate for scaling or close variants. Business Emails receives comparable traffic but weaker activation depth — especially repeat usage — so the next step is to audit onboarding and the first-use path. Since the dataset does not include spend, page renders, or revenue, this report does not calculate CAC, ROAS, LTV, or page-render CVR.

  • Academic Writing LP: 22.6% Activation CVR vs 18.5% for Business Emails — a 4.1pp aggregate gap
  • Repeat Try Rate gap: 75.3% vs 12.2% — the largest signal in the dataset
  • Shared issue: 43–51% dead install rate across both LPs — a post-install problem, not an LP problem
  • Feature alignment is strong: 99.7% of academic users try academic_citation_helper; 100% of business users try smart_email_reply
  • QA: all 8 automated checks returned zero flagged rows on this mock dataset
LP Funnel Comparison
Key finding: Both LPs received near-identical traffic (1,596 vs 1,604 clicks). The performance gap is entirely in activation quality: Academic Writing LP converts 22.6% of clicks to try_grammarly vs 18.5% for Business Emails — a 4.1pp aggregate gap on near-identical volume; the cohort trend shows the same general pattern, though daily cohorts vary.
Shared leak: 43–51% of users who install Grammarly never trigger try_grammarly within 7 days. This suggests a shared post-install activation problem, not only an LP acquisition problem.

Data Limitations
What this dataset cannot measure: The following metrics require fields not present in this dataset and are not claimed anywhere in this report: CAC (no ad spend) · ROAS (no spend or revenue) · LTV (no subscription events) · Ad CTR (no impressions) · LP page-render CVR (no render events — did_click_lp is install-button click, not page view) · Retention beyond 7 days (outside attribution window).

Next instrumentation priorities: (1) Add page render events to calculate LP CVR. (2) Add ad spend per LP for CAC/ROAS. (3) Add subscription events for LTV. (4) Add onboarding step events between install and first try to diagnose the 43–51% dead install rate.

Technical note: This standalone report uses embedded CSV outputs and Chart.js loaded from CDN (cdn.jsdelivr.net). An internet connection is required to render charts. For production, the same metric layer should connect directly to governed BI tables with live data refresh and access controls.
